# 1.6a Sprite renderer: tiles, players, bullets, camera (proposed split of 1.6)

**Size:** M · **Area:** `gg_client` · **Depends on:** PRs #28–#30 merged

## Goal

`uv run python -m gg_client` looks like the v1 game during a round.

## What to build

A class `SpriteRenderer` in `gg_client/sprite_renderer.py` that implements the `Renderer` protocol in `gg_client/renderer.py`. Use `gg_client/debug_renderer.py` as the worked example: same constructor, same `load_level` and `draw`, same camera and Y-flip maths. Then switch `gg_client/__main__.py` to use it.

- Load every image once in `__init__` (never per frame) and scale it once:
  - tiles: `data/images/tiles/<type>/<variant>.png`, scaled to `level.tile_size`
  - players: `data/images/entities/player/<action>/` for `p1`... see the note on naming below
  - bullet: `data/images/bullet3.png` at 35×15; health bar: `data/images/health_simple.png`
- Animation frame for a player: `frames[(p["action_ticks"] // duration) % len(frames)]`, with duration 6 for `idle`, 4 for `run`, 5 for `jump` and `wall_slide` (v1's values).
- Flip the sprite horizontally when `p["facing"] == -1`.
- Draw the gun (`data/images/_gun.png`, 15×13) at `x + 21, y + 15` facing right, `x, y + 15` facing left.

## Naming note

v1 drew the WASD player with `entities/player2` and the numpad player with `entities/player`. In the new code the WASD player is `p1`. So: `p1` → `entities/player2`, `p2` → `entities/player`.
